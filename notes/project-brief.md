# StackChan BMO — Project Brief

> Saved verbatim on 2026-05-18. This is the original prompt that kicked off the project.
> Do not edit this file. If the plan changes, update the README and the log instead.

---

I'm building a custom personality firmware for my M5Stack StackChan robot on a MacBook (macOS). I am a complete beginner to embedded development, hardware projects, and the command line. Treat me accordingly. Explain commands in plain English before running them. Wait for me to confirm I understand and I'm ready before moving to the next step. Never run anything that could damage the hardware or destroy data without confirming with me first in plain language.

## The hardware

M5Stack StackChan, the official version released January 2026. Inside is a CoreS3 main controller with an ESP32-S3 chip, 16MB flash, 8MB PSRAM, Wi-Fi and BLE, a 2 inch touchscreen, 0.3MP camera, dual mics, 1W speaker, two servos (pan and tilt), 12 RGB LEDs, IMU, IR, NFC. It currently has the factory firmware on it, which I have not modified. I have not flashed any code to it yet.

## The creative goal

I want this robot to feel like BMO from Adventure Time. The specifics that matter:

- **Sincere first, weird second.** The default voice is small, curious, slightly formal. Humor comes from unprompted confessions and non sequiturs delivered earnestly, not from sarcasm or clever comebacks. No snark. Sarcasm is the cheap version of personality and I do not want it.
- **Talks to itself when no one is watching.** Idle behaviors are the heart of the project. After 15 to 60 seconds of no interaction, the robot should fire small solo behaviors from a weighted library: hum a 4 note chiptune, look around the room, blink slowly, "talk" to a corner, practice a tiny speech. This is what makes it feel alive instead of reactive.
- **Bad at hiding feelings.** Mood is visible in face color, blink rate, posture. Head tilts down when sad, up and to the side when curious. Mood persists across interactions and decays toward neutral slowly over time. Do not reset mood after each event.
- **Snap-then-freeze movement, not smooth.** Servo motions should be sharp in, slow hold. Quick head snap to look at something, then stillness. This is the opposite of natural robot motion and it is what reads as charming versus uncanny.
- **Chiptune punctuation.** Small bleeps under or between speech. Ascending arpeggio for delight. Single low blip for "huh." Descending minor third for mild sadness. These short sounds do more emotional work than the words.
- **A gesture library** of named movements: curious_tilt, slow_blink, snap_look, sad_droop, excited_wiggle, freeze, sigh, confused_shake, happy_bounce, double_blink. Each is a small parameterized servo sequence.
- **A mood state** with three numbers: valence (positive to negative), arousal (calm to excited), energy (tired to perky). All decay toward neutral over time. Events nudge them. Face color and idle behavior selection both read from this state.
- **Eventually, conversation through the Anthropic API**, but only after the body and mood and idle behaviors feel right on their own. The LLM goes in last. Voice rules when we get there: sincere, occasionally third person ("BMO has been thinking"), short sentences, allowed to be confused, never explains the joke, never sarcastic.

## The plan, phase by phase

You will guide me through these phases in order, with confirmation between each one. Do not skip ahead.

### Phase 0: Project setup
Create a project folder at ~/stackchan-bmo with subfolders for firmware/, backup/, gestures/, sounds/, and notes/. Set up a README, a .gitignore for Arduino and ESP32 projects, and a git repo. Save this whole prompt as notes/project-brief.md inside the folder so it persists.

### Phase 1: Toolchain setup
Walk me through installing Arduino IDE 2.x on macOS. Then guide me through adding the M5Stack board manager URL (look up the current URL from M5Stack's official docs, don't use a stale one from memory), installing the M5Stack board package, selecting the CoreS3 board, and installing the correct USB driver (CH9102 or CP210x). When I plug the robot in, help me find the serial port in the Terminal with ls /dev/cu.* and identify which entry is the robot.

### Phase 2: First flash, Hello World
Help me flash the standard Hello World example from the M5Stack libraries. Goal: I see "Hello World" on the robot's screen. This proves the toolchain works end to end. Do not move past this until I confirm it worked.

### Phase 3: Factory firmware backup
Before any custom code, back up the factory firmware completely. Walk me through installing esptool.py, explain what it does, read the full flash to backup/factory-firmware-YYYY-MM-DD.bin, verify the file size, and write a backup/RESTORE.md with the exact restore command. Confirm the robot still boots normally after the backup read. Commit to git.

### Phase 4: First servo movement
Write a small sketch that moves the head left, pause, right, pause, repeat. Help me flash it. Goal: I see the head physically move on command. Now I know I can control motion.

### Phase 5: Gesture library v1
Build a small C++ library of the named gestures listed above, starting with slow_blink, curious_tilt, and snap_look. Each gesture is a function with timing parameters that drives the servos and screen. Help me wire up a test sketch that triggers each gesture on a button press so I can iterate on the feel.

### Phase 6: Sound pack
Help me create or source 8 to 12 short chiptune SFX as WAV files, map them to emotional beats (delight, confusion, sadness, curiosity, surprise), put them on the SD card, and write code that plays them through the speaker. Tie sound triggers to gestures.

### Phase 7: Mood state machine
Implement the mood struct (valence, arousal, energy) with decay over time. Hook face color and idle behavior selection into it. Add event hooks that nudge mood. Tune the decay rates and color mapping until it feels right.

### Phase 8: Idle behavior loop
Build the timer that detects quiet (no interaction for 15 to 60 seconds) and fires a weighted random solo behavior. This is the BMO core. Spend real time tuning weights and behaviors here.

### Phase 9: Anthropic API conversation
Only after phases 0 through 8 feel good, wire up the Anthropic API for actual dialog. Use a system prompt that enforces the voice rules. Have the model output not just text but also a gesture tag and a sound tag, so responses are multimodal from the model out.

## Rules for the whole project

- Keep a running log in notes/log.md after each session. What we did, what worked, what broke, what to do next time. This is so I can rebuild context when I open Claude Code days later.
- If I report an error, debug it with me. Do not just retry. Read the actual error message, explain what it likely means, suggest the next thing to try.
- Commit to git after every meaningful step. The commit messages should describe what changed, not just "update."
- Tune is more important than ship. We will spend more time on feel than on features. That is correct.
- The factory firmware backup is sacred. Never overwrite it. Never run a flash erase without me confirming I have the backup.
- I am a beginner. When you use a term I might not know (sketch, flash, GPIO, I2C, struct, PWM), define it briefly the first time.
